# 문제 1. 환경변수로 GMS 채팅 모델 연결하기

<a id="question1"></a>

## 문제

프로젝트 루트의 `.env`에 저장된 `GMS_KEY`를 노출하지 않고 불러와 SSAFY GMS의 OpenAI 호환 API에 연결된 LangChain 채팅 모델을 생성하려 한다. 다음 흐름의 빈칸을 채우시오.

## 요구사항

- `.env`의 값을 현재 프로세스 환경변수에 등록한다.
- `GMS_KEY`를 읽어 `ChatOpenAI`의 인증값으로 전달한다.
- 모델은 `gpt-5.4-mini`, 엔드포인트는 `https://gms.ssafy.io/gmsapi/api.openai.com/v1/`이다.
- 키 원문을 출력하지 않는다.

## 제공 코드 또는 스켈레톤

```text
[A] .env 로드
 입력: 프로젝트 루트의 .env
 출력: 현재 프로세스의 환경변수
        ↓
[B] ______________________________
 입력: 환경변수 이름 "GMS_KEY"
 출력: API 키 문자열 또는 None
        ↓
[C] ______________________________
 입력: model, api_key, base_url
 출력: GMS에 연결된 ChatOpenAI 객체
        ↓
[D] 프롬프트 전달 및 답변 본문 추출
 입력: 문자열 프롬프트
 출력: ____________________________
```

[정답으로 이동](#answer1)

---

<a id="answer1"></a>

## 정답

- [B] `os.getenv("GMS_KEY")`로 키 읽기
- [C] `ChatOpenAI(...)` 객체 생성
- [D] `llm.invoke(prompt).content`로 얻은 문자열

## 정답 코드

```python
import os
from dotenv import load_dotenv
from langchain_openai import ChatOpenAI

load_dotenv()
api_key = os.getenv("GMS_KEY")

llm = ChatOpenAI(
    model="gpt-5.4-mini",
    api_key=api_key,
    base_url="https://gms.ssafy.io/gmsapi/api.openai.com/v1/",
)

answer = llm.invoke("환경변수를 한 문장으로 설명하세요.").content
print(answer)
```

## 핵심 해설

- 실행 순서는 `.env` 로드 → 키 조회 → 모델 객체 생성 → 호출 → `.content` 추출이다.
- `load_dotenv()`의 출력보다 환경변수 등록이라는 부수 효과가 중요하다. `os.getenv`는 키가 없으면 `None`을 반환한다.
- `ChatOpenAI`의 입력은 모델 설정이고, `invoke`의 입력은 프롬프트, 출력은 메시지 객체이다.
- 다른 모델로 바꾸려면 [C]의 `model`, 다른 중계 서버를 쓰려면 `base_url`, 다른 키 이름을 쓰려면 [B]를 수정한다.
- `.env`는 버전 관리에서 제외하고 키 전체를 로그에 출력하지 않는다.

# 문제 2. Zero-shot, Few-shot, 단계별 풀이 프롬프트 선택

<a id="question2"></a>

## 문제

하나의 채팅 모델로 세 가지 작업을 처리한다. 각 작업에 알맞은 프롬프팅 블록과 공통 호출 흐름을 채우시오.

## 요구사항

- 단순 감성 분류는 예시 없이 수행한다.
- 출력 형식을 안정시키려는 감성 분류는 입력→출력 예시 2개를 포함한다.
- 산술 문제는 중간 계산이 포함된 풀이 예시를 제공한다.
- 세 방식 모두 같은 LLM 호출 API를 사용한다.

## 제공 코드 또는 스켈레톤

```text

                   단계별 중간 계산 + 새 문제
                          ↓
공통 [D] _________________________________
                          ↓
응답 메시지의 [E] ____________에서 문자열 추출
```

- 단계별 풀이 예시는 중간 계산의 순서를 전달한다. 실제 서비스에서는 불필요한 내부 추론 공개를 요구하기보다 검산 가능한 핵심 계산과 최종 답 형식을 명시할 수 있다.
- 레이블이 세 종류로 바뀌면 프롬프트의 허용 레이블과 Few-shot 예시를 함께 바꾼다. 계산 문제 유형이 바뀌면 풀이 예시 블록을 바꾼다.

# 문제 3. OpenAI 클라이언트로 생성 파라미터 제어하기

<a id="question3"></a>

## 문제

SSAFY GMS에 OpenAI 공식 클라이언트로 연결하여 채팅 요청을 보내고 첫 답변을 출력하려 한다. 흐름의 빈칸을 채우시오.

## 요구사항

- `messages`는 역할과 내용을 가진 딕셔너리의 리스트여야 한다.
- 모델은 `gpt-5.4-mini`이다.
- `temperature=1.0`, 최대 생성 길이는 500 토큰으로 설정한다.
- GPT-5 계열에 맞는 출력 토큰 제한 인자를 사용한다.

## 제공 코드 또는 스켈레톤

```text
환경변수의 GMS_KEY
        ↓
[A] OpenAI(api_key=..., base_url=...)
        ↓
[B] 요청 메시지 구성: _________________________________
        ↓
[C] __________________________________________ 호출
    model + messages + temperature + [D] __________________
        ↓
응답 객체
        ↓
[E] __________________________________________ 문자열 추출
```

[정답으로 이동](#answer3)

---

<a id="answer3"></a>

## 정답

- [B] `[{'role': 'user', 'content': 'AI의 미래를 한 문장으로'}]`
- [C] `client.chat.completions.create(...)`
- [D] `max_completion_tokens=500`
- [E] `response.choices[0].message.content`

## 정답 코드

```python
import os
from dotenv import load_dotenv
from openai import OpenAI

load_dotenv()
client = OpenAI(
    api_key=os.getenv("GMS_KEY"),
    base_url="https://gms.ssafy.io/gmsapi/api.openai.com/v1/",
)

response = client.chat.completions.create(
    model="gpt-5.4-mini",
    messages=[{"role": "user", "content": "AI의 미래를 한 문장으로"}],
    temperature=1.0,
    max_completion_tokens=500,
)
print(response.choices[0].message.content)
```

## 핵심 해설

- 클라이언트 생성 → 메시지 리스트 구성 → completions 호출 → 첫 choice의 본문 추출 순서다.
- `messages`는 `[{"role": "user", "content": "..."}]` 형식이다. 대화 맥락은 같은 형식의 원소를 순서대로 추가해 전달한다.
- `temperature`는 출력 다양성, `max_completion_tokens`는 생성 가능한 최대 출력 길이를 제어한다. 실습의 GPT-5 계열은 `temperature=1`만 지원하며 `max_tokens` 대신 `max_completion_tokens`를 쓴다.
- 모델 변경은 `model`, 출력 길이 변경은 [D], 프롬프트 변경은 [B]를 수정한다.

# 문제 4. JSON Schema로 합성 리뷰 구조 강제하기

<a id="question4"></a>

## 문제

LLM이 고객 리뷰 3개를 생성하되, 응답이 항상 `reviews` 배열을 가진 JSON이 되도록 강제한다. 처리 흐름의 빈칸을 채우시오.

## 요구사항

- 리뷰 한 건은 `customer_name: string`, `rating: integer`, `category: string`, `text: string`을 가진다.
- 네 필드는 모두 필수이며 정의하지 않은 필드는 허용하지 않는다.
- 최상위 객체에서도 `reviews`는 필수이며 추가 필드를 허용하지 않는다.
- 스키마는 `llm.invoke`의 `response_format`으로 전달한다.

## 제공 코드 또는 스켈레톤

```text
[A] JSON Schema 작성
 최상위 object
   └─ properties.reviews: [B] __________
       └─ items: object
           ├─ properties: 네 필드와 타입
           ├─ [C] ______________________________
           └─ [D] ______________________________
        ↓
[E] response_format 래퍼 작성
 type="json_schema", name, strict=True, schema=[A]
        ↓
[F] llm.invoke(prompt, __________________________)
        ↓
AIMessage.content의 JSON 문자열
        ↓
[G] __________________ → 파이썬 dict → result["reviews"]
```

[정답으로 이동](#answer4)

---

<a id="answer4"></a>

## 정답

- [B] `array`
- [C] `required=["customer_name", "rating", "category", "text"]`
- [D] `additionalProperties=False`
- [F] `response_format=review_response_format`
- [G] `json.loads(response.content)`

## 정답 코드

```python
import json

review_schema = {
    "type": "object",
    "properties": {
        "reviews": {
            "type": "array",
            "items": {
                "type": "object",
                "properties": {
                    "customer_name": {"type": "string"},
                    "rating": {"type": "integer"},
                    "category": {"type": "string"},
                    "text": {"type": "string"},
                },
                "required": ["customer_name", "rating", "category", "text"],
                "additionalProperties": False,
            },
        }
    },
    "required": ["reviews"],
    "additionalProperties": False,
}

review_response_format = {
    "type": "json_schema",
    "json_schema": {
        "name": "customer_reviews",
        "strict": True,
        "schema": review_schema,
    },
}

response = llm.invoke(
    "이어폰 리뷰 3개를 생성하세요. 긍정, 부정, 중립을 하나씩 포함하세요.",
    response_format=review_response_format,
)
result = json.loads(response.content)
print(result["reviews"])
```

## 핵심 해설

- 스키마 내부 구조 정의 → `response_format` 래핑 → 호출 시 전달 → JSON 문자열 파싱 순서다.
- `properties`는 허용 필드와 타입, `required`는 필수 필드, `additionalProperties: False`는 미정의 필드 금지 역할을 한다.
- 배열 개수와 감성별 개수는 현재 프롬프트가 담당한다. 필드 구조 변경은 스키마의 `properties`와 `required`를 함께 수정한다.
- `response.content`는 여전히 문자열이므로 `json.loads`를 거쳐야 `result["reviews"]`로 접근할 수 있다.

# 문제 5. 페르소나×상품 조합으로 데이터 증강하고 저장하기

<a id="question5"></a>

## 문제

페르소나 3개와 상품 2개의 모든 조합에 대해 리뷰를 하나씩 생성하고, 생성 조건을 함께 기록한 뒤 UTF-8 JSON 파일로 저장한다. 빈 처리 블록을 채우시오.

## 요구사항

- 총 6개의 리뷰를 생성한다.
- 각 결과는 `persona`, `product`, `review` 키를 가진 딕셔너리이다.
- 한글이 `\uXXXX`로 변환되지 않게 저장하고 들여쓰기 2칸을 적용한다.

## 제공 코드 또는 스켈레톤

```text
personas(3개) + products(2개)
        ↓
[A] __________________________________________
        ↓ 각 (persona, product)
[B] f-string으로 조건별 프롬프트 생성
        ↓
[C] __________________________________________
        ↓ 문자열 review
[D] 결과와 생성 조건을 딕셔너리로 묶어 results에 추가
        ↓
[E] __________________________________________
    ensure_ascii=False, indent=2
        ↓
synthetic_reviews.json
```

[정답으로 이동](#answer5)

---

<a id="answer5"></a>

## 정답

- [A] 페르소나와 상품을 순회하는 이중 반복문
- [C] `llm.invoke(prompt).content`
- [E] `json.dump(results, f, ensure_ascii=False, indent=2)`

## 정답 코드

```python
import json

personas = ["20대 대학생", "40대 주부", "60대 은퇴자"]
products = ["노트북", "운동화"]
results = []

for persona in personas:
    for product in products:
        prompt = f"{persona}의 관점에서 {product} 리뷰를 작성하세요."
        review = llm.invoke(prompt).content
        results.append({
            "persona": persona,
            "product": product,
            "review": review,
        })

with open("synthetic_reviews.json", "w", encoding="utf-8") as f:
    json.dump(results, f, ensure_ascii=False, indent=2)
```

## 핵심 해설

- 조건 목록 정의 → 카테시안 곱 순회 → 프롬프트 생성 → LLM 호출 → 메타데이터 결합 → 파일 저장 순서다.
- `invoke`의 메시지 객체에서 `.content`를 꺼내야 JSON 직렬화 가능한 문자열이 된다.
- 결과 딕셔너리에 생성 조건을 함께 저장해야 데이터의 출처와 분포를 추적할 수 있다.
- 페르소나가 `P`개, 상품이 `Q`개이면 호출과 결과는 `P×Q`개이다. 생성량은 두 입력 리스트를 수정하고, 출력 필드는 `append` 블록을 수정한다.
- `json.dump`는 파일 객체를 받으며 `ensure_ascii=False`가 한글 보존, `indent=2`가 가독성을 담당한다.

# 문제 6. LLM 평가 결과로 품질 필터링하기

<a id="question6"></a>

## 문제

리뷰마다 구체성·자연스러움·유용성을 1~5점으로 평가하고, 세 점수의 평균인 `total`이 3.5 이상인 결과만 남긴다. 처리 흐름을 완성하시오.

## 요구사항

- 평가 프롬프트에는 리뷰가 들어갈 `{review_text}` 자리와 JSON 출력 예시가 있어야 한다.
- 템플릿 안의 JSON 중괄호는 `str.format`에서 치환되지 않아야 한다.
- 응답을 딕셔너리로 파싱해 리스트에 모은다.
- 필터링 후 통과율을 백분율로 계산한다.

## 제공 코드 또는 스켈레톤

```text
평가 기준 + "리뷰: {review_text}" + JSON 예시 템플릿
        ↓
[A] __________________________________________
        ↓ 완성된 평가 prompt
[B] __________________________________________
        ↓ AIMessage.content(JSON 문자열)
[C] __________________________________________
        ↓ 점수 dict를 results에 누적
[D] __________________________________________
        ↓ filtered
[E] len(filtered) / len(results) * 100
```

[정답으로 이동](#answer6)

---

<a id="answer6"></a>

## 정답

- [A] `eval_prompt.format(review_text=review_text)`
- [B] `llm.invoke(prompt)`
- [C] `json.loads(response.content)`
- [D] `[r for r in results if r["total"] >= 3.5]`

## 정답 코드

```python
import json

eval_prompt = """다음 리뷰를 구체성, 자연스러움, 유용성 기준으로 각각 1-5점 평가하세요.
리뷰: {review_text}
JSON으로 답하세요. total은 세 점수의 평균입니다.
{{"specificity": 1, "naturalness": 1, "usefulness": 1, "total": 1, "reason": "근거"}}"""

def evaluate_review(review_text, llm):
    prompt = eval_prompt.format(review_text=review_text)
    response = llm.invoke(prompt)
    return json.loads(response.content)

reviews = ["좋아요.", "배터리가 8시간 가고 무게가 200g이라 휴대하기 좋습니다."]
results = [evaluate_review(review, llm) for review in reviews]
threshold = 3.5
filtered = [r for r in results if r["total"] >= threshold]
pass_rate = len(filtered) / len(results) * 100 if results else 0.0
print(f"통과율: {pass_rate:.1f}%")
```

## 핵심 해설

- 템플릿 정의 → 리뷰 삽입 → LLM 호출 → JSON 파싱 → 누적 → 임계값 필터 → 통과율 계산 순서다.
- `str.format` 템플릿에서 실제 치환 자리는 `{review_text}`, JSON 예시의 리터럴 중괄호는 `{{`와 `}}`로 쓴다.
- `response.content`의 문자열이 `json.loads`를 거쳐 `total`, `reason` 등의 키를 가진 딕셔너리로 전달된다.
- 평가 기준 변경은 템플릿과 JSON 필드를, 합격 기준 변경은 `threshold`를, 평가 대상을 바꾸려면 `reviews` 입력 블록을 수정한다.
- 빈 입력에서 0으로 나누는 일을 막기 위해 통과율 계산 전에 `results`의 존재를 확인한다.
