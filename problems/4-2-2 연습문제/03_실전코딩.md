## 문제 1. 반복 개선형 보고서 에이전트

## 문제

사용자가 입력한 보고서 주제에 대해 계획을 세우고, 보고서를 작성하고, 품질을 평가하는 LangGraph 애플리케이션을 구현하라. 평가에서 개선이 필요하다고 판단하면 계획 단계부터 다시 실행한다.

## 요구사항

- 공유 상태는 `task`, `plan`, `results`, `reflection`을 가진다.
- `results`는 모든 실행 결과를 순서대로 누적한다.
- 계획은 3단계로 생성한다.
- Worker 결과는 300자 이내가 되도록 요청한다.
- Reflection은 최근 Worker 결과를 평가하여 부족한 경우 `개선 필요`라는 문구와 구체적 내용을, 충분한 경우 `완성도 충분`을 출력하게 한다.
- 결과가 2개 쌓이면 평가 내용과 관계없이 종료한다.
- 결과가 2개 미만이고 평가에 `개선`이 포함되면 계획 단계로 돌아간다. 그 외에는 종료한다.
- 그래프 스텝 상한은 10으로 설정한다.
- 입력은 `{"task": "고객 불만 분석 보고서 작성", "results": []}`이고, 최종 누적 결과 수와 최종 평가를 출력한다.

## 정답 코드

```python
import os
import operator
from typing import Annotated, List, TypedDict

from dotenv import load_dotenv
from langchain_openai import ChatOpenAI
from langgraph.graph import END, START, StateGraph

load_dotenv()
llm = ChatOpenAI(
    model="gpt-5-mini",
    api_key=os.environ["GMS_KEY"],
    base_url="https://gms.ssafy.io/gmsapi/api.openai.com/v1/",
)

class AgentState(TypedDict):
    task: str
    plan: str
    results: Annotated[List[str], operator.add]
    reflection: str

def planner(state: AgentState):
    plan = llm.invoke(
        f"다음 작업의 실행 계획을 3단계로 간결하게 세워주세요: {state['task']}"
    ).content
    return {"plan": plan}

def worker(state: AgentState):
    result = llm.invoke(
        f"다음 계획에 따라 작업을 300자 이내로 실행하세요: {state['plan']}"
    ).content
    return {"results": [result]}

def reflection(state: AgentState):
    review = llm.invoke(
        f"""작업: {state['task']}
최근 결과: {state['results'][-1]}
결과를 평가하세요. 부족하면 '개선 필요: 구체적 내용'으로,
충분하면 '완성도 충분'으로 답하세요."""
    ).content
    return {"reflection": review}

def evaluate(state: AgentState):
    if len(state["results"]) >= 2:
        return "end"
    if "개선" in state["reflection"]:
        return "planner"
    return "end"

builder = StateGraph(AgentState)
builder.add_node("planner", planner)
builder.add_node("worker", worker)
builder.add_node("reflection", reflection)
builder.add_edge(START, "planner")
builder.add_edge("planner", "worker")
builder.add_edge("worker", "reflection")
builder.add_conditional_edges(
    "reflection", evaluate, {"planner": "planner", "end": END}
)

app = builder.compile()
result = app.invoke(
    {"task": "고객 불만 분석 보고서 작성", "results": []},
    config={"recursion_limit": 10},
)
print(f"실행 결과 수: {len(result['results'])}")
print(f"최종 평가: {result['reflection']}")
```

## 핵심 해설

- `planner`의 `plan`이 Worker의 입력으로, Worker가 누적한 최신 `results[-1]`이 Reflection의 입력으로 전달된다.
- 각 노드는 전체 상태가 아닌 자신이 갱신할 키만 딕셔너리로 반환한다.
- `Annotated[..., operator.add]`와 `[result]` 반환 형식이 함께 있어야 결과가 누적된다.
- 최대 반복 횟수는 `evaluate()`, 그래프 전체 안전 한도는 `recursion_limit`에서 바꾼다.
- 평가 문구를 변경하면 Reflection 프롬프트와 `evaluate()`의 문자열 검사 조건을 함께 변경해야 한다.

## 문제 2. 병렬 전문가 분석 시스템

## 문제

한 주제를 조사 관점과 분석 관점에서 병렬 처리하고 두 결과를 하나의 답변으로 종합하는 Supervisor 그래프를 구현하라.

## 요구사항

- 상태는 `task`, 누적형 `worker_results`, `next_action`, `final_output`을 가진다.
- Supervisor는 Worker 결과가 없을 때 분배를, 하나 이상 있을 때 종합을 선택한다.
- 조사 Worker와 분석 Worker는 같은 `task`를 입력받아 각각 한 번 실행된다.
- 각 Worker 결과 앞에 `[조사]`, `[분석]`을 붙인다.
- 두 Worker는 병렬 분기되고, 모두 완료된 후 Supervisor로 합류한다.
- 종합 노드는 누적 결과를 줄바꿈으로 연결하여 LLM에 전달한다.
- 입력은 `{"task": "AI 시장 동향 분석", "worker_results": []}`이다.
- Worker 결과 수와 최종 출력을 출력한다.

## 정답

## 정답 코드

```python
import os
import operator
from typing import Annotated, List, TypedDict

from dotenv import load_dotenv
from langchain_openai import ChatOpenAI
from langgraph.graph import END, START, StateGraph

load_dotenv()
llm = ChatOpenAI(
    model="gpt-5-nano",
    api_key=os.environ["GMS_KEY"],
    base_url="https://gms.ssafy.io/gmsapi/api.openai.com/v1/",
)

class SupervisorState(TypedDict):
    task: str
    worker_results: Annotated[List[str], operator.add]
    next_action: str
    final_output: str

def supervisor(state: SupervisorState):
    if not state.get("worker_results"):
        return {"next_action": "distribute"}
    return {"next_action": "synthesize"}

def worker_research(state: SupervisorState):
    result = llm.invoke(f"다음 주제를 조사하세요: {state['task']}").content
    return {"worker_results": [f"[조사] {result}"]}

def worker_analysis(state: SupervisorState):
    result = llm.invoke(f"다음 주제를 분석하세요: {state['task']}").content
    return {"worker_results": [f"[분석] {result}"]}

def synthesize(state: SupervisorState):
    combined = "\n".join(state["worker_results"])
    final = llm.invoke(f"다음 전문가 결과를 하나로 종합하세요:\n{combined}").content
    return {"final_output": final}

def route_supervisor(state: SupervisorState):
    if state["next_action"] == "distribute":
        return ["research", "analysis"]
    return "synthesize"

builder = StateGraph(SupervisorState)
builder.add_node("supervisor", supervisor)
builder.add_node("research", worker_research)
builder.add_node("analysis", worker_analysis)
builder.add_node("synthesize", synthesize)
builder.add_edge(START, "supervisor")
builder.add_conditional_edges("supervisor", route_supervisor)
builder.add_edge("research", "supervisor")
builder.add_edge("analysis", "supervisor")
builder.add_edge("synthesize", END)

app = builder.compile()
result = app.invoke({"task": "AI 시장 동향 분석", "worker_results": []})
print(f"Worker 결과 수: {len(result['worker_results'])}")
print(f"최종 출력: {result['final_output']}")
```

## 핵심 해설

- 최초 Supervisor 출력 `next_action='distribute'`가 노드 이름 리스트로 변환되어 Fan-out을 만든다.
- Worker의 `{"worker_results": [문자열]}` 출력 두 개는 reducer를 통해 하나의 리스트가 된다.
- 두 Worker의 복귀 엣지가 Supervisor에서 Fan-in되고, 두 번째 방문에서는 `synthesize`로 이동한다.
- 전문가를 추가하려면 상태 형식은 유지한 채 Worker 함수, 노드 등록, 분기 리스트, 복귀 엣지를 추가한다.
- 전문가별 입력이 달라지면 각 Worker의 프롬프트를, 최종 형식이 달라지면 `synthesize()`를 수정한다.

## 정답

## 정답 코드

```python
import json
import os
import re

from dotenv import load_dotenv
from langchain_openai import ChatOpenAI

load_dotenv()
llm = ChatOpenAI(
    model="gpt-5-nano",
    api_key=os.environ["GMS_KEY"],
    base_url="https://gms.ssafy.io/gmsapi/api.openai.com/v1/",
)

def evaluate_multi_agent(state: dict) -> dict:
    prompt = f"""당신은 Multi-Agent 시스템 평가자입니다.

## 평가 기준
1. Planner (0~30): 작업 분배의 적절성과 역할 구분
2. Worker (0~40): 실행 품질, 정보의 충실도와 정확성
3. Overall (0~30): 요청 충족도와 최종 결과의 완성도

## 입력
- 사용자 요청: {state['task']}
- Worker 결과: {state.get('worker_results', [])}
- 최종 출력: {state.get('final_output', '없음')}

다음 키를 가진 JSON만 출력하세요. 다른 텍스트는 쓰지 마세요.
{{"planner_score": <0~30>, "worker_score": <0~40>,
"overall_score": <0~30>, "feedback": "<총평>"}}"""

    content = llm.invoke(prompt).content
    try:
        match = re.search(r"```(?:json)?\s*([\s\S]*?)\s*```", content)
        if match:
            json_str = match.group(1)
        else:
            match = re.search(r"\{[\s\S]*\}", content)
            json_str = match.group(0) if match else content

        parsed = json.loads(json_str)
        total = (
            parsed["planner_score"]
            + parsed["worker_score"]
            + parsed["overall_score"]
        )
        return {
            "score": total,
            "feedback": parsed["feedback"],
            "details": {
                "planner": parsed["planner_score"],
                "worker": parsed["worker_score"],
                "overall": parsed["overall_score"],
            },
        }
    except Exception as error:
        return {
            "score": 0,
            "feedback": f"평가 실패: {error}\n원본 응답: {content}",
            "details": {},
        }

sample_state = {
    "task": "AI 시장 동향 분석",
    "worker_results": ["[조사] 시장 자료", "[분석] 전망 자료"],
    "final_output": "시장 동향 종합 결과",
}
print(evaluate_multi_agent(sample_state))
```

## 핵심 해설

- 그래프 최종 상태가 평가 프롬프트의 입력이 되고, 평가 LLM의 `.content`는 다시 파싱할 문자열이 된다.
- 코드 블록의 `group(1)`과 중괄호 전체의 `group(0)`은 서로 다른 매치 그룹을 사용한다.
- `json.loads()` 결과에서 세 점수를 합산하고 외부 반환 키를 `score`, `feedback`, `details`로 정규화한다.
- 배점을 바꾸면 프롬프트 범위와 총점 해석을, 키 이름을 바꾸면 프롬프트·파싱 후 접근·반환 매핑을 함께 수정한다.
- 입력 리스트 형식은 `worker_results: list[str]`이며, 최종 출력은 문자열이어야 평가 프롬프트가 의도대로 구성된다.
