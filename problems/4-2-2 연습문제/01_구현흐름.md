## 문제 1. Planner–Worker와 Reflection 반복

## 문제

다음은 사용자의 작업을 계획하고 실행한 뒤, 결과에 개선이 필요하면 다시 계획하는 처리 흐름이다. 빈칸 A~E에 들어갈 처리 블록 또는 실행 단계를 작성하라.

`START → [A] → [B] → [C] → [D] → END`

단, D는 다음 조건을 적용하는 조건부 분기이다.

- 실행 결과가 2개 이상이면 종료한다.
- 최근 평가에 `"개선"`이 포함되면 A로 돌아간다.
- 그 외에는 종료한다.
- 상태의 `results`는 기존 결과를 덮어쓰지 않고 누적되어야 한다.
- 그래프 실행 시 빈칸 E에 들어갈 초기 상태를 함께 쓰라.

## 요구사항

- A~C에는 노드 이름과 그 노드의 입력·출력을 쓴다.
- D에는 분기 함수의 반환값과 실제 목적지의 대응 관계를 쓴다.
- E에는 `invoke()`에 전달할 최소 초기 상태를 쓴다.

<a id="answer1"></a>

## 정답

- A: `planner` — `task`를 읽고 `plan`을 반환
- B: `worker` — `plan`을 읽고 `results: [새 결과]`를 반환
- C: `reflection` — `task`와 `results[-1]`을 읽고 `reflection`을 반환
- D: `evaluate` — `"planner"`는 `planner`, `"end"`는 `END`로 연결
- E: `{"task": "고객 불만 분석 보고서 작성", "results": []}`

## 정답 코드

```python
import operator
from typing import Annotated, List, TypedDict
from langgraph.graph import END, START, StateGraph

class AgentState(TypedDict):
    task: str
    plan: str
    results: Annotated[List[str], operator.add]
    reflection: str

def planner(state: AgentState):
    plan = llm.invoke(
        f"다음 작업의 실행 계획을 3단계로 간결하게 세워주세요: {state['task']}"
    ).content
    return {"plan": plan}

def worker(state: AgentState):
    result = llm.invoke(
        f"다음 계획을 300자 이내로 실행하세요: {state['plan']}"
    ).content
    return {"results": [result]}

def reflection(state: AgentState):
    review = llm.invoke(
        f"작업: {state['task']}\n결과: {state['results'][-1]}\n"
        "부족하면 '개선 필요: 구체적 내용', 충분하면 '완성도 충분'이라고 평가하세요."
    ).content
    return {"reflection": review}

def evaluate(state: AgentState):
    if len(state["results"]) >= 2:
        return "end"
    if "개선" in state["reflection"]:
        return "planner"
    return "end"

graph = StateGraph(AgentState)
graph.add_node("planner", planner)
graph.add_node("worker", worker)
graph.add_node("reflection", reflection)
graph.add_edge(START, "planner")
graph.add_edge("planner", "worker")
graph.add_edge("worker", "reflection")
graph.add_conditional_edges(
    "reflection", evaluate, {"planner": "planner", "end": END}
)

app = graph.compile()
result = app.invoke(
    {"task": "고객 불만 분석 보고서 작성", "results": []},
    config={"recursion_limit": 10},
)
print(result)
```

위 코드는 실습에서 초기화한 `llm`을 사용한다.

## 핵심 해설

- 실행 순서는 계획 → 실행 → 평가이며, 평가 결과에 따라 계획부터 반복한다.
- `Annotated[List[str], operator.add]`는 각 Worker 반환값의 리스트를 기존 리스트에 결합한다.
- Worker는 문자열이 아니라 `{"results": [result]}`처럼 리스트를 반환해야 reducer가 올바르게 작동한다.
- 반복 횟수를 바꾸려면 `evaluate()`의 상한을, 평가 기준을 바꾸려면 `reflection()` 프롬프트와 분기 조건을 수정한다.
- `recursion_limit`은 상태 값이 아니라 `invoke()`의 `config`에 전달한다.

## 문제 2. Supervisor Fan-out/Fan-in

## 문제

하나의 작업을 조사 Worker와 분석 Worker에게 동시에 분배한 뒤 결과를 종합하려 한다. 아래 흐름의 빈칸 A~F를 채워라.

```text
START → [A]
          ├─ distribute → [B] ─┐
          └─ distribute → [C] ─┴→ [D] → synthesize → END
          └─ synthesize ───────────────────┘
```

## 요구사항

- A와 D는 같은 중앙 관리자 노드이다.
- B와 C는 같은 입력 상태를 받아 서로 다른 관점의 결과를 만든다.
- B와 C가 반환한 값은 상태 필드 E에 자동 누적된다.
- A의 분기 함수는 최초 방문 시 두 Worker 이름을 담은 F 형식으로 반환해야 한다.
- 두 Worker 완료 후 A를 다시 방문하면 종합 노드로 이동해야 한다.

[정답으로 이동](#answer2)

---

<a id="answer2"></a>

## 정답

- A, D: `supervisor`
- B: `research`
- C: `analysis`
- E: `worker_results`
- F: 리스트 `['research', 'analysis']`

## 정답 코드

```python
import operator
from typing import Annotated, List, TypedDict
from langgraph.graph import END, START, StateGraph

class SupervisorState(TypedDict):
    task: str
    worker_results: Annotated[List[str], operator.add]
    next_action: str
    final_output: str

def supervisor(state: SupervisorState):
    if not state.get("worker_results"):
        return {"next_action": "distribute"}
    return {"next_action": "synthesize"}

def worker_research(state: SupervisorState):
    result = llm.invoke(f"조사: {state['task']}").content
    return {"worker_results": [f"[조사] {result}"]}

def worker_analysis(state: SupervisorState):
    result = llm.invoke(f"분석: {state['task']}").content
    return {"worker_results": [f"[분석] {result}"]}

def synthesize(state: SupervisorState):
    combined = "\n".join(state["worker_results"])
    final = llm.invoke(f"다음 결과를 종합하세요:\n{combined}").content
    return {"final_output": final}

def route_supervisor(state: SupervisorState):
    if state["next_action"] == "distribute":
        return ["research", "analysis"]
    return "synthesize"

graph = StateGraph(SupervisorState)
graph.add_node("supervisor", supervisor)
graph.add_node("research", worker_research)
graph.add_node("analysis", worker_analysis)
graph.add_node("synthesize", synthesize)
graph.add_edge(START, "supervisor")
graph.add_conditional_edges("supervisor", route_supervisor)
graph.add_edge("research", "supervisor")
graph.add_edge("analysis", "supervisor")
graph.add_edge("synthesize", END)

app = graph.compile()
result = app.invoke({"task": "AI 시장 동향 분석", "worker_results": []})
print(result["final_output"])
```

위 코드는 실습에서 초기화한 `llm`을 사용한다.

## 핵심 해설

- 첫 Supervisor 방문은 Fan-out을 결정하고, 두 Worker의 완료가 Fan-in 장벽을 거쳐 두 번째 Supervisor 방문으로 합쳐진다.
- 두 Worker의 입력은 `task`, 출력은 각각 한 원소를 가진 `worker_results` 리스트다.
- `route_supervisor()`가 노드 이름의 리스트를 반환하는 것이 병렬 분배의 핵심이다.
- Worker를 추가하려면 노드 등록, 분기 반환 리스트, Worker→Supervisor 엣지를 함께 수정해야 한다.
- 종합 방식이 바뀌면 그래프 연결보다 `synthesize()`의 결합 방식과 프롬프트를 수정한다.

## 문제 3. LLM-as-a-Judge 평가 흐름

## 문제

멀티 에이전트의 최종 상태를 100점 만점으로 평가한다. 다음 처리 블록을 올바른 순서로 배열하고, 각 블록이 전달하는 데이터 형식을 쓰라.

- (가) 세 점수를 합산하고 `score`, `feedback`, `details`를 구성한다.
- (나) 평가 기준과 상태를 포함한 프롬프트를 만든다.
- (다) Markdown 코드 블록 또는 중괄호 구간에서 JSON 문자열을 추출한다.
- (라) LLM을 호출하여 응답의 `content`를 얻는다.
- (마) `json.loads()`로 문자열을 딕셔너리로 변환한다.
- (바) 파싱 실패 시 0점과 원문을 포함한 오류 결과를 반환한다.

## 요구사항

- 배점은 Planner 30점, Worker 40점, Overall 30점이다.
- LLM에는 JSON만 출력하도록 지시한다.
- 정상 반환 형식과 실패 반환 형식을 모두 제시한다.

[정답으로 이동](#answer3)

---

<a id="answer3"></a>

## 정답

정상 흐름은 `(나) → (라) → (다) → (마) → (가)`이며, (다)~(가)에서 예외가 발생하면 `(바)`로 이동한다.

## 정답 코드

```python
import json
import re

def evaluate_multi_agent(state: dict) -> dict:
    prompt = f"""멀티 에이전트 결과를 평가하세요.
Planner 0~30, Worker 0~40, Overall 0~30으로 채점하세요.
요청: {state['task']}
Worker 결과: {state.get('worker_results', [])}
최종 출력: {state.get('final_output', '없음')}
다음 JSON만 출력하세요:
{{"planner_score": 0, "worker_score": 0, "overall_score": 0, "feedback": "평가"}}"""
    content = llm.invoke(prompt).content

    try:
        match = re.search(r"```(?:json)?\s*([\s\S]*?)\s*```", content)
        if match:
            json_str = match.group(1)
        else:
            match = re.search(r"\{[\s\S]*\}", content)
            json_str = match.group(0) if match else content

        parsed = json.loads(json_str)
        score = (
            parsed["planner_score"]
            + parsed["worker_score"]
            + parsed["overall_score"]
        )
        return {
            "score": score,
            "feedback": parsed["feedback"],
            "details": {
                "planner": parsed["planner_score"],
                "worker": parsed["worker_score"],
                "overall": parsed["overall_score"],
            },
        }
    except Exception as error:
        return {
            "score": 0,
            "feedback": f"평가 실패: {error}\n원본 응답: {content}",
            "details": {},
        }
```

위 코드는 실습에서 초기화한 `llm`을 사용한다.

## 핵심 해설

- 입력은 `task`, `worker_results`, `final_output`을 가진 상태 딕셔너리이고, LLM 출력은 먼저 문자열이다.
- `re.search()`는 코드 펜스 안 JSON을 우선 추출하고, 없으면 가장 바깥 중괄호 구간을 사용한다.
- `json.loads()` 이후에야 키 접근과 점수 합산이 가능하다.
- 배점이나 평가 항목이 바뀌면 프롬프트, 합산식, `details` 매핑을 함께 수정해야 한다.
- 실전 서비스에서는 파싱뿐 아니라 점수 범위와 필수 키 검증도 추가하는 것이 안전하다.
