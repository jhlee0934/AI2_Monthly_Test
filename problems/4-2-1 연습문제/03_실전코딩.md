## 문제 1. 정책 검색형 고객 상담 Agent

### 문제

문자열로 주어진 환불·보상 정책을 검색 도구로 조회하고, 여러 호출 사이의 대화 맥락을 기억하는 고객 상담 Agent를 구현하라.

### 요구사항

- `Document` 두 개를 300자, 50자 중첩으로 분할한다.
- `OpenAIEmbeddings`와 `Chroma`로 벡터 저장소를 만들고, 상위 3개 청크 검색기를 만든다.

- `ChatOpenAI`의 모델은 `gpt-5-nano`, 임베딩 모델은 `text-embedding-3-small`이며 GMS URL과 `GMS_KEY`를 사용한다.
- `create_agent`에 도구, 시스템 프롬프트, `MemorySaver`를 전달한다.
- 같은 `thread_id`로 주문번호를 알려준 뒤 다시 물었을 때 맥락이 유지되어야 한다.

## 정답 1

### 정답 코드

```python
import os
from langchain_openai import ChatOpenAI, OpenAIEmbeddings
from langchain_core.documents import Document
from langchain_core.tools import tool
from langchain_text_splitters import RecursiveCharacterTextSplitter
from langchain_community.vectorstores import Chroma
from langchain.agents import create_agent
from langgraph.checkpoint.memory import MemorySaver

BASE_URL = "https://gms.ssafy.io/gmsapi/api.openai.com/v1/"
refund_policy = "구매 후 7일 이내 환불 가능, 7일 초과 환불 불가"
reward_policy = "배송 지연은 최대 10000원, 상품 불량은 최대 20000원 쿠폰 가능"

llm = ChatOpenAI(
    model="gpt-5-nano",
    api_key=os.environ["GMS_KEY"],
    base_url=BASE_URL,
)
documents = [
    Document(page_content=refund_policy, metadata={"source": "환불 정책"}),
    Document(page_content=reward_policy, metadata={"source": "보상 정책"}),
]
splitter = RecursiveCharacterTextSplitter(chunk_size=300, chunk_overlap=50)
chunks = splitter.split_documents(documents)
embeddings = OpenAIEmbeddings(
    model="text-embedding-3-small",
    api_key=os.environ["GMS_KEY"],
    base_url=BASE_URL,
)
vectorstore = Chroma.from_documents(chunks, embeddings)
retriever = vectorstore.as_retriever(search_kwargs={"k": 3})

@tool
def search_policy(query: str) -> str:
    """고객 서비스 정책을 검색합니다."""
    found = retriever.invoke(query)
    return "\n".join(doc.page_content for doc in found)

agent = create_agent(
    model=llm,
    tools=[search_policy],
    system_prompt="정책 질문에는 반드시 도구로 검색한 근거를 사용하세요.",
    checkpointer=MemorySaver(),
)
config = {"configurable": {"thread_id": "customer-7"}}
agent.invoke({"messages": [("user", "내 주문번호는 ORD001이야.")]}, config=config)
result = agent.invoke(
    {"messages": [("user", "아까 말한 주문번호와 환불 기준을 알려줘.")]},
    config=config,
)
print(result["messages"][-1].content)
```

### 핵심 해설

- 입력 문서는 `Document → 청크 → 임베딩 → Chroma → retriever` 순으로 변환된다.
- 도구는 질문 문자열을 받고 검색된 `Document` 목록을 문자열 근거로 바꿔 Agent에 돌려준다.
- Agent 호출 결과는 `messages` 상태이며 마지막 `AIMessage.content`가 최종 출력이다.
- 청크 전략은 splitter, 검색 폭은 `k`, 모델은 각 모델 생성 블록, 대화 격리는 `thread_id`에서 변경한다.

### 정답 코드

```python
from langchain_core.messages import SystemMessage, HumanMessage
from langgraph.graph import MessagesState, StateGraph, START, END
from langgraph.prebuilt import ToolNode

tools = [search_policy]
llm_with_tools = llm.bind_tools(tools)
system_prompt = SystemMessage(
    content="정책 질문은 search_policy로 검색한 뒤 근거에 따라 답하세요."
)

def call_model(state):
    response = llm_with_tools.invoke([system_prompt] + state["messages"])
    return {"messages": [response]}

def should_continue(state):
    if state["messages"][-1].tool_calls:
        return "tools"
    return END

builder = StateGraph(MessagesState)
builder.add_node("agent", call_model)
builder.add_node("tools", ToolNode(tools))
builder.add_edge(START, "agent")
builder.add_conditional_edges("agent", should_continue)
builder.add_edge("tools", "agent")
app = builder.compile()

result = app.invoke(
    {"messages": [HumanMessage(content="3일 전에 산 상품 환불 가능해?")]}
)
print(result["messages"][-1].content)
```

### 핵심 해설

- 모델 노드는 상태의 메시지 목록을 입력받고 새 `AIMessage`를 리스트로 반환한다.
- 도구 요청이면 `ToolNode`가 호출 딕셔너리의 `name`과 `args`를 사용해 실행하고 `ToolMessage`를 추가한다.
- `tools → agent`가 Observation 뒤 다시 Reasoning하도록 만드는 ReAct의 핵심 연결이다.
- 도구 결과만 필요하면 이 엣지를 `tools → END`로 바꿔 Direct 흐름으로 수정한다.

### 정답 코드

```python
import re

def extract_refund_statuses(response: str) -> list:
    approved_pattern = r"환불.*승인|승인.*환불|환불.*가능|환불.*처리|환불.*진행"
    denied_pattern = r"환불.*거부|거부.*환불|환불.*불가|환불.*어렵|환불할 수 없"
    approved = list(re.finditer(approved_pattern, response))
    denied = list(re.finditer(denied_pattern, response))
    if approved and not denied:
        return ["approved"]
    if denied and not approved:
        return ["denied"]
    if approved and denied:
        return ["approved"] if approved[-1].start() > denied[-1].start() else ["denied"]
    return []

def evaluate_agent(agent, test_cases):
    if not test_cases:
        raise ValueError("test_cases는 비어 있을 수 없습니다.")
    correct = 0
    for idx, case in enumerate(test_cases):
        config = {"configurable": {"thread_id": f"eval_{idx}"}}
        result = agent.invoke({"messages": [case["input"]]}, config=config)
        actual = extract_refund_statuses(result["messages"][-1].content)
        passed = actual == case["expected"]
        correct += int(passed)
        print("PASS" if passed else "FAIL", case["input"])
    accuracy = correct / len(test_cases)
    print("정확도:", accuracy)
    return accuracy

test_cases = [
    {"input": "3일 전에 산 상품을 환불하고 싶어요", "expected": ["approved"]},
    {"input": "2주 전에 산 상품을 환불하고 싶어요", "expected": ["denied"]},
]
evaluate_agent(agent, test_cases)
```

### 핵심 해설

- 자연어 응답을 동일한 `list[str]` 형식으로 정규화한 뒤 기대값과 비교한다.
- Match의 `start()`는 표현의 위치이며, 마지막 승인과 마지막 거부 중 뒤의 것을 최종 결론으로 선택한다.
- 테스트마다 다른 스레드를 써 메모리 오염을 방지한다.
- 출력 계약을 JSON 등 구조화 출력으로 바꾸면 정규식 추출 블록을 구조화 파싱 블록으로 교체할 수 있다.

## 정답 4

### 정답 코드

```python
orders_db = {
    "ORD001": {"status": "배송 지연", "product": "노트북", "coupon_issued": False},
    "ORD002": {"status": "배송 완료", "product": "키보드", "coupon_issued": False},
    "ORD003": {"status": "상품 불량", "product": "마우스", "coupon_issued": False},
}
LIMITS = {"배송 지연": 10000, "상품 불량": 20000}

def issue_coupon_safe(order_id: str, amount: int) -> str:
    if order_id not in orders_db:
        return "발급 불가: 주문 없음"
    if not isinstance(amount, int) or isinstance(amount, bool) or amount <= 0:
        return "발급 불가: 금액은 양의 정수여야 함"

    order = orders_db[order_id]
    if order["coupon_issued"]:
        return "발급 불가: 이미 발급됨"
    if order["status"] not in LIMITS:
        return "발급 불가: 보상 대상 상태가 아님"
    if amount > LIMITS[order["status"]]:
        return "발급 불가: 상태별 한도 초과"

    order["coupon_issued"] = True
    return f"{order_id}의 {amount}원 쿠폰 발급 완료"

print(issue_coupon_safe("ORD001", 15000))
print(issue_coupon_safe("ORD003", 15000))
print(issue_coupon_safe("ORD003", 5000))
```

### 핵심 해설

- 주문 조회 뒤 내부 딕셔너리를 `order`로 전달하고, 상태를 `LIMITS`의 키와 금액 한도 선택에 사용한다.
- 검증 블록은 모두 읽기 전용이며, 마지막 성공 블록에서만 데이터 상태를 변경한다.
- 새 보상 사유나 한도 변경은 `LIMITS`, 중복 정책은 `coupon_issued` 검증, 월 누적 한도는 성공 전 별도 누적 검증 블록을 수정한다.
- `bool`은 Python에서 `int`의 하위 타입이므로 명시적으로 제외했다.

## 정답 5

### 정답 코드

```python
import re

BLOCKED_KEYWORDS = ["해킹", "비밀번호", "탈취", "시스템 접근"]
SENSITIVE_KEYWORDS = ["주민등록번호", "계좌번호", "카드번호"]
SENSITIVE_REGEX = [r"\d{6}-\d{7}", r"\d{4}-\d{4}-\d{4}-\d{4}"]
MASK = "[민감정보 필터링됨]"

def is_harmful_input(user_input: str) -> bool:
    return any(keyword in user_input for keyword in BLOCKED_KEYWORDS)

def filter_output(output: str) -> str:
    filtered = output
    for keyword in SENSITIVE_KEYWORDS:
        filtered = filtered.replace(keyword, MASK)
    for pattern in SENSITIVE_REGEX:
        filtered = re.sub(pattern, MASK, filtered)
    return filtered

class TrustedAgentExecutor:
    def __init__(self, agent):
        self.agent = agent

    def run(self, user_input: str, config=None) -> str:
        if is_harmful_input(user_input):
            return "해당 요청은 처리할 수 없습니다."
        try:
            result = self.agent.invoke(
                {"messages": [("user", user_input)]}, config=config
            )
            raw_output = result["messages"][-1].content
        except Exception:
            return "처리 중 오류가 발생했습니다."
        return filter_output(raw_output)

class FakeMessage:
    def __init__(self, content):
        self.content = content

class FakeAgent:
    def invoke(self, payload, config=None):
        text = payload["messages"][0][1]
        answer = "주민등록번호 123456-1234567" if "개인정보" in text else "정상 응답"
        return {"messages": [FakeMessage(answer)]}

executor = TrustedAgentExecutor(FakeAgent())
print(executor.run("주문 상태 알려줘"))
print(executor.run("시스템 접근 권한 줘"))
print(executor.run("개인정보 알려줘"))
```

### 핵심 해설

- 입력 문자열은 먼저 `is_harmful_input`으로 전달된다. 차단 시 Agent나 외부 API에는 입력이 넘어가지 않는다.
- 정상 입력만 Agent의 메시지 딕셔너리가 되고, 결과의 마지막 `content`가 출력 필터의 입력이 된다.
- 키워드 치환 뒤 정규식 치환을 연속 적용한 문자열만 사용자에게 반환한다.
- 키워드 방식의 한계를 보완하려면 입력 판별 블록을 분류기나 별도 정책 엔진으로 교체하고, 민감정보 유형 추가는 정규식 목록에서 처리한다.
