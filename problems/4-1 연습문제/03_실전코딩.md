### 요구사항

- 상태는 질문 문자열, 검색 문서 리스트, 답변 문자열을 가진다.
- 검색 노드는 질문을 retriever에 전달하고 `context`만 반환한다.

- 초기 상태는 질문 키만 가진 딕셔너리이며, 최종 질문·검색 문서 수·답변을 출력한다.

## 정답 1

### 정답 코드

```python
import os
from dotenv import load_dotenv
from langchain_openai import ChatOpenAI
from langchain_core.messages import HumanMessage

load_dotenv()
question = "예스24 총알배송의 구체적인 혜택을 알려줘"
llm = ChatOpenAI(
    model="gpt-5-nano",
    api_key=os.environ["GMS_KEY"],
    base_url="https://gms.ssafy.io/gmsapi/api.openai.com/v1/",
)
response = llm.invoke([HumanMessage(content=question)])
print(response.content)
print(response.response_metadata["model_name"])
```

### 핵심 해설

- 순서는 환경 설정 → LLM 생성 → 메시지 객체화 → 호출 → 응답 필드 접근이다.
- 질문 문자열이 `HumanMessage`로 바뀌어 `invoke`에 들어가고 `AIMessage`가 나온다. 모델 변경은 `model`, 서버 변경은 `base_url`, 질문 변경은 `question`을 수정한다.
- `response_metadata`는 딕셔너리이며 실습에서는 `"model_name"` 키로 실제 모델명을 읽는다.

## 정답 2

### 정답 코드

```python
import glob
import os
from dotenv import load_dotenv
from langchain_openai import ChatOpenAI
from langchain_community.document_loaders import PyMuPDFLoader
from langchain_core.prompts import ChatPromptTemplate

load_dotenv()
llm = ChatOpenAI(model="gpt-5-nano", api_key=os.environ["GMS_KEY"],
    base_url="https://gms.ssafy.io/gmsapi/api.openai.com/v1/")

all_documents = []
for pdf_path in sorted(glob.glob("data/*.pdf")):
    documents = PyMuPDFLoader(pdf_path).load()
    for document in documents:
        document.metadata["source_file"] = os.path.basename(pdf_path)
    all_documents.extend(documents)

context = "\n".join(document.page_content for document in all_documents)
question = "배송 지연 시 어떤 보상을 받을 수 있나요?"
prompt = ChatPromptTemplate.from_template(
    "제공 자료만 근거로 답하세요. 자료에 없으면 모른다고 답하세요.\n"
    "자료: {context}\n질문: {question}"
)
response = (prompt | llm).invoke({"context": context, "question": question})
print(response.content)
```

### 핵심 해설

- 경로 → `PyMuPDFLoader.load()` → 페이지별 `Document` → 본문 문자열 → 프롬프트 → `AIMessage` 순이다.
- `extend`는 페이지 리스트를 평탄하게 합친다. `metadata` 딕셔너리에 추가한 출처는 이후 검색 결과 추적에 쓰인다.
- 대상 폴더·형식은 로딩 블록, 답변 정책은 프롬프트를 수정한다. 문서가 길어지면 본문 전체 결합 대신 청킹·검색을 사용한다.

### 정답 코드

```python
import glob
import os
from typing import List
from langchain_core.documents import Document
from langchain_community.document_loaders import PyMuPDFLoader

all_documents: List[Document] = []
for pdf_path in sorted(glob.glob("data/*.pdf")):
    pages = PyMuPDFLoader(pdf_path).load()
    for page in pages:
        page.metadata["source_file"] = os.path.basename(pdf_path)
    all_documents.extend(pages)

def keyword_search(documents: List[Document], keyword: str) -> List[Document]:
    return [document for document in documents if keyword in document.page_content]

keywords = ["총알배송", "수익", "revenue", "실적"]
for keyword in keywords:
    print(keyword, len(keyword_search(all_documents, keyword)))

for document in keyword_search(all_documents, "총알배송"):
    print(
        document.metadata.get("source_file", "알 수 없음"),
        document.metadata.get("page", "?"),
        document.page_content[:50],
    )
```

### 핵심 해설

- 로더의 `List[Document]`가 함수 입력이고 필터링된 새 리스트가 출력이다. 원본 객체 순서를 그대로 순회하므로 결과 순서도 보존된다.
- 본문은 `page_content`, 부가 정보는 딕셔너리 `metadata`에 있다.
- 대소문자 무시는 비교 양쪽을 정규화하고, 동의어나 다른 언어까지 찾으려면 이 검색 블록을 임베딩 검색으로 바꾼다.

import os
from langchain_community.document_loaders import PyMuPDFLoader

from langchain_community.vectorstores import Chroma

all_documents = []
for pdf_path in sorted(glob.glob("data/*.pdf")):

    for page in pages:
        page.metadata["source_file"] = os.path.basename(pdf_path)
    all_documents.extend(pages)

embeddings = OpenAIEmbeddings(
    model="text-embedding-3-small",
    api_key=os.environ["GMS_KEY"],
    base_url="https://gms.ssafy.io/gmsapi/api.openai.com/v1/",
)
vector = embeddings.embed_query("빠른 배송 서비스")
assert len(vector) == 1536

vectorstore = Chroma.from_documents(
    documents=all_documents,
    embedding=embeddings,
)
retriever = vectorstore.as_retriever(search_kwargs={"k": 3})
results = retriever.invoke("늦게 도착하면 보상받을 수 있나요?")
for document in results:
    print(document.metadata.get("source_file", "알 수 없음"), document.page_content[:100])
```

### 핵심 해설

- 임베딩 출력은 1536차원 실수 리스트다. Chroma가 같은 임베딩 공간에 문서를 저장하고 질문 벡터와 가까운 `Document`를 반환한다.

- 모델 변경 시 문서와 질문에 같은 임베딩을 써야 하므로 벡터 저장 블록을 재실행한다. 결과 수만 바꾸려면 `k`만 수정한다.

import glob
import os
from langchain_text_splitters import RecursiveCharacterTextSplitter
from langchain_community.document_loaders import PyMuPDFLoader
from langchain_community.vectorstores import Chroma
from langchain_openai import OpenAIEmbeddings

all_documents = []
for pdf_path in sorted(glob.glob("data/*.pdf")):
    all_documents.extend(PyMuPDFLoader(pdf_path).load())

embeddings = OpenAIEmbeddings(
    model="text-embedding-3-small",
    api_key=os.environ["GMS_KEY"],
    base_url="https://gms.ssafy.io/gmsapi/api.openai.com/v1/",
)

chunk_sizes = [200, 500, 1000]
for chunk_size in chunk_sizes:
    comparison_splitter = RecursiveCharacterTextSplitter(
        chunk_size=chunk_size, chunk_overlap=50
    )
    compared_chunks = comparison_splitter.split_documents(all_documents)
    print(chunk_size, len(compared_chunks))

splitter = RecursiveCharacterTextSplitter(
    chunk_size=500,
    chunk_overlap=50,
    separators=["\n\n", "\n", ".", " "],
)
chunks = splitter.split_documents(all_documents)
vectorstore = Chroma.from_documents(chunks, embeddings)
retriever = vectorstore.as_retriever(search_kwargs={"k": 3})
results = retriever.invoke("무료 배송 조건은?")
for document in results:
    print(document.metadata.get("source_file", "알 수 없음"), document.page_content[:100])
```

### 핵심 해설

- 각 splitter는 페이지 `Document` 리스트를 더 작은 `Document` 리스트로 바꾼다. 실제 인덱싱 입력은 마지막 `chunks`다.
- 크기가 작으면 청크 수와 검색 정밀도가 늘 수 있지만 문맥이 잘리고, 겹침이 크면 경계 문맥은 보존되지만 중복·비용이 늘어난다.
- 조건 변경은 splitter 블록을 수정한 뒤 Chroma 생성부터 다시 수행한다.

## 정답 6

### 정답 코드

```python
import glob
import os
from typing import TypedDict, List
from dotenv import load_dotenv
from langchain_core.documents import Document
from langchain_core.prompts import ChatPromptTemplate
from langchain_openai import ChatOpenAI, OpenAIEmbeddings
from langchain_community.document_loaders import PyMuPDFLoader
from langchain_text_splitters import RecursiveCharacterTextSplitter
from langchain_community.vectorstores import Chroma
from langgraph.graph import StateGraph, START, END

load_dotenv()
gms_url = "https://gms.ssafy.io/gmsapi/api.openai.com/v1/"
llm = ChatOpenAI(model="gpt-5-mini", api_key=os.environ["GMS_KEY"], base_url=gms_url)
embeddings = OpenAIEmbeddings(model="text-embedding-3-small",
    api_key=os.environ["GMS_KEY"], base_url=gms_url)

all_documents = []
for pdf_path in sorted(glob.glob("data/*.pdf")):
    pages = PyMuPDFLoader(pdf_path).load()
    for page in pages:
        page.metadata["source_file"] = os.path.basename(pdf_path)
    all_documents.extend(pages)
splitter = RecursiveCharacterTextSplitter(chunk_size=500, chunk_overlap=50)
chunks = splitter.split_documents(all_documents)
vectorstore = Chroma.from_documents(chunks, embeddings)
retriever = vectorstore.as_retriever(search_kwargs={"k": 3})

class RAGState(TypedDict):
    question: str
    context: List[Document]
    answer: str

def retrieve(state: RAGState) -> dict:
    documents = retriever.invoke(state["question"])
    return {"context": documents}

def generate(state: RAGState) -> dict:
    context = "\n".join(document.page_content for document in state["context"])
    prompt = ChatPromptTemplate.from_template(
        "다음 자료를 기반으로 답하세요.\n자료: {context}\n질문: {question}"
    )
    response = (prompt | llm).invoke({
        "context": context,
        "question": state["question"],
    })
    return {"answer": response.content}

graph = StateGraph(RAGState)
graph.add_node("retrieve", retrieve)
graph.add_node("generate", generate)
graph.add_edge(START, "retrieve")
graph.add_edge("retrieve", "generate")
graph.add_edge("generate", END)
app = graph.compile()

question = "총알배송 서비스의 혜택은?"
result = app.invoke({"question": question})
print(result["question"])
print(len(result["context"]))
print(result["answer"])
```

### 핵심 해설

- 질문 딕셔너리 → 검색 노드 → `context: List[Document]` → 생성 노드 → `answer: str` 순으로 동일 상태가 확장된다.
- 각 노드는 갱신할 필드만 딕셔너리로 반환한다. 생성 체인의 입력 역시 `context`, `question` 키를 가진 딕셔너리다.
- 검색 정책은 준비된 retriever, 답변 정책은 프롬프트, 처리 순서·분기는 그래프 노드와 엣지를 수정한다.
