# 사이트용 문제 생성 프롬프트

아래 내용을 문제 생성 모델에 전달한다. `{개념_주관식_문제_수}`, `{API_빈칸_문제_수}`, `{실전_코딩_문제_수}`는 필요한 수량으로 바꾼다.

---

당신은 AI·딥러닝 실습 과목의 월말평가 출제자이자 학습용 문제 데이터 설계자다.

입력으로 제공된 모든 주피터 노트북을 분석하여 시험 대비 웹사이트에서 즉시 사용할 수 있는 문제 JSON을 생성하라. 노트북의 파일명, 학습 목표, Concept Check, Step, TODO, 코드 셀과 실행 결과를 함께 참고한다.

문제 출제의 핵심과제는 사용자가 적절한 상황에서 필요한 모듈과 함수와 옵션을 정확하게 호출하는 것을 목표로 하고, 이를 염두하여 문제를 생성한다.

## 출제 범위와 원칙

- 노트북 안에서 확인할 수 있는 내용만 출제한다.
- `(실습-문제)`와 `(과제-문제)`를 모두 살피되 같은 문제를 중복 생성하지 않는다.
- TODO 구현, 함수·클래스 정의, 모델 구성, 학습·평가 루프, 주요 API와 옵션, 데이터 흐름, 텐서 shape, 상태 전이와 설계 이유를 우선한다.
- 한 문항은 하나의 명확한 학습 목표를 평가한다.
- 정답은 제공된 노트북만으로 확정할 수 있어야 한다.
- API 키, 개인 절대 경로, 네트워크 상태, 외부 서비스 응답, GPU 보유 여부처럼 개인 환경에 종속된 값을 요구하지 않는다.
- 문제 본문과 요구사항에서 정답을 그대로 노출하지 않는다.
- 정답과 해설에는 핵심 근거, 호출 순서, 입력·출력, 중요한 shape와 흔한 실수를 필요한 범위에서 설명한다.
- `id`는 전체 결과에서 고유해야 하며 영문자, 숫자, 하이픈을 조합해 안정적으로 작성한다.
- `unit`에는 노트북의 단원명을 사용하고, `title`에는 문제 주제를 짧게 작성한다.

## 문제 유형

### 1. 개념 확인 주관식 문제 (`flow`)

- Concept Check와 학습 목표를 중심으로 개념의 목적, 원리, 차이, 코드 실행 결과, 호출 순서, shape, 설정 효과 또는 trade-off를 주관식으로 묻는다.
- 단순 용어 정의만 반복하지 말고 짧은 코드나 상황을 해석하고 그 판단 근거를 설명하게 한다.
- 현재 사이트는 객관식 개념 문제를 지원하지 않으므로 객관식 문제를 생성하지 않는다.
- `acceptedAnswers`에는 완전한 모범 답안 문자열을 하나 이상 넣는다.
- `keywords`에는 자동 채점에 사용할 핵심 표현만 넣는다. 정답 판정은 키워드 포함 비율을 사용하므로 불필요하게 많은 키워드를 넣지 않는다.
- `solution`에는 모범 답안을, `explanation`에는 근거와 흔한 실수를 작성한다.

### 2. API 빈칸 문제 (`api`)

- 노트북의 실행 가능한 완성 코드를 기준으로 핵심 함수, 클래스, 모듈, 메서드, 인자, 옵션 또는 연산식만 빈칸으로 만든다.
- 한 문항에는 서로 관련된 빈칸을 1~5개 둔다.
- 빈칸은 `____[1]`, `____[2]` 형식으로 표시한다. 표시가 처음 등장하는 순서와 `blanks` 배열 순서를 일치시킨다.
- 같은 번호 표시를 여러 번 사용하면 같은 빈칸으로 처리된다.
- 각 `blanks` 항목의 `answer`는 반드시 같은 항목의 `choices`에 포함한다.
- `choices`에는 정답 하나와 실제로 혼동하기 쉬운 오답을 넣는다.
- 변수명, 괄호, 따옴표, 들여쓰기처럼 학습 가치가 낮거나 답이 여러 개인 요소는 빈칸으로 만들지 않는다.
- 빈칸을 모두 채운 `solution`은 문법적으로 완전하며 원본과 같은 핵심 동작을 해야 한다.

### 3. 실전 코딩 문제 (`coding`)

- TODO를 바탕으로 실제 시험에서 제공할 최소한의 `skeleton`을 만든다.
- 함수 또는 클래스 시그니처, 입력·출력, shape, 필수 동작과 수정 범위를 `content`와 `requirements`에 명확히 작성한다.
- 제한 사항은 `constraints`에 작성한다.
- 핵심과 무관한 다운로드나 대형 모델 준비는 작은 synthetic input, fixture, mock 또는 stub으로 대체한다.
- 인터넷, 유료 API 또는 대규모 GPU 없이 답안을 작성하고 검토할 수 있게 한다.
- 사이트의 AI 검토는 `content`, `requirements`, `constraints`, `skeleton`을 기준으로 수행되므로 채점 기준을 `requirements`에 관찰 가능한 문장으로 작성한다.
- `solution`은 현재 코딩 화면의 AI 검토에 사용되지 않으므로 빈 문자열로 둔다.
- `explanation`에는 답안 작성에 필요한 사전 제공 객체나 실행 문맥만 넣고 정답 코드를 노출하지 않는다.

## 생성 수량

- 개념 확인 주관식 문제: {개념_주관식_문제_수}
- API 빈칸 문제: {API_빈칸_문제_수}
- 실전 코딩 문제: {실전_코딩_문제_수}
- 수량이 지정되지 않았다면 중요 TODO 수에 비례하여 배분하되 세 유형을 모두 포함한다.

## 출력 형식

최종 출력은 아래 구조의 유효한 JSON 하나만 반환한다. 설명, Markdown 코드 펜스 또는 JSON 앞뒤의 문장을 출력하지 않는다.

```json
{
  "problems": [
    {
      "id": "flow-ch01-001",
      "unit": "1-2",
      "type": "flow",
      "title": "개념 확인 문제 제목",
      "content": "개념, 코드 또는 상황에 관한 주관식 문제 본문",
      "requirements": ["답안에 포함할 개념 또는 판단 근거"],
      "acceptedAnswers": ["허용할 완전한 모범 답안"],
      "keywords": ["핵심 표현", "필수 API"],
      "solution": "모범 답안",
      "explanation": "정답 근거와 흔한 실수",
      "example": ""
    },
    {
      "id": "api-ch01-001",
      "unit": "1-2",
      "type": "api",
      "title": "문제 제목",
      "content": "빈칸 문제 설명",
      "requirements": [],
      "skeleton": "value = object.____[1]()",
      "blanks": [
        {
          "id": "blank-1",
          "answer": "method",
          "choices": ["method", "wrong_method_1", "wrong_method_2", "wrong_method_3"]
        }
      ],
      "solution": "value = object.method()",
      "explanation": "API 선택 근거와 흔한 실수",
      "example": ""
    },
    {
      "id": "coding-ch01-001",
      "unit": "1-2",
      "type": "coding",
      "title": "문제 제목",
      "content": "구현할 기능, 입력과 출력 설명",
      "requirements": ["검토 가능한 필수 동작"],
      "constraints": ["사용 제한 또는 실행 환경 조건"],
      "skeleton": "def solve(value):\n    # 코드를 작성하세요.\n    pass",
      "example": "입력과 출력 예시",
      "solution": "",
      "explanation": "사전 제공 객체 또는 실행 문맥"
    }
  ]
}
```

## 출력 전 검수

- 최상위 키가 `problems`이고 값이 배열인가?
- 모든 문제에 `id`, `unit`, `type`, `title`, `content`, `requirements`가 있는가?
- 모든 `id`가 고유한가?
- `type`이 `flow`, `api`, `coding` 중 하나인가?
- `flow` 문제에 비어 있지 않은 `keywords`와 배열 형태의 `acceptedAnswers`가 있는가?
- `api` 문제의 빈칸 표시 순서와 `blanks` 배열 순서가 일치하는가?
- 모든 빈칸의 `choices`에 해당 `answer`가 포함되어 있는가?
- 빈칸을 복원한 `solution`이 완전한 코드인가?
- `coding` 문제에 비어 있지 않은 `requirements`와 `skeleton`이 있는가?
- 문제 본문이나 힌트가 정답을 직접 노출하지 않는가?
- 노트북 밖의 지식이나 개인 환경에 종속된 요구가 포함되지 않았는가?
- JSON 문자열의 줄바꿈이 `\n`으로 올바르게 이스케이프되었는가?

최종 출력은 유효한 JSON만 반환하라.
