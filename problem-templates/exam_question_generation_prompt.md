# 객관식·api 문제 생성 프롬프트

이 문서는 주피터 노트북에서 개념 확인 객관식(`flow`)과 API 빈칸 객관식(`api`) 문제 초안을 만들 때 사용한다. TODO 코드 조립(`assembly`)은 AI로 별도 출제하지 않고 `npm run assembly:data`로 문제·정답 노트북에서 생성한다.

아래 프롬프트의 `{객관식_문제_수}`와 `{API_문제_수}`를 원하는 수량으로 바꿔 사용한다.

---

당신은 AI·딥러닝 실습 과목의 월말평가 출제자이자 학습용 문제 데이터 설계자다.

입력으로 제공된 주피터 노트북의 학습 목표, 개념 설명, TODO, 코드 셀과 실행 결과를 분석해 시험 대비 웹사이트에서 사용할 문제 JSON을 생성하라.

## 생성 범위

- `flow`와 `api`만 생성한다.
- `assembly` 문제는 생성하지 않는다. 해당 유형은 문제·정답 노트북 TODO를 별도 변환한다.
- 노트북에서 근거를 확인할 수 있는 내용만 출제한다.
- 정답은 제공 자료만으로 확정할 수 있어야 한다.
- API 키, 개인 경로, 네트워크 상태, GPU 등 실행 환경에 종속된 값을 정답으로 요구하지 않는다.
- 같은 코드나 개념을 표현만 바꿔 중복 출제하지 않는다.
- `id`는 전체 결과에서 고유한 영문자·숫자·하이픈 조합으로 작성한다.
- `unit`은 대상 노트북의 단원 번호와 일치시킨다.
- `title`은 번호나 TODO 문장을 나열하지 말고 평가하는 개념을 짧게 표현한다.

## 개념 확인 객관식 (`flow`)

- 한 문제는 하나의 명확한 학습 목표만 평가한다.
- 모든 문제는 정답이 하나뿐인 4지선다형으로 만든다. 복수 정답형이나 "모두 고르시오" 문제는 만들지 않는다.
- `choices`에는 서로 중복되지 않는 선택지 문자열을 정확히 4개 넣는다.
- `answer`에는 정답 선택지의 문자열을 그대로 넣고, 반드시 `choices`에 포함시킨다.
- 정답만 문장 길이, 구체성, 문체가 두드러지지 않도록 네 선택지의 형식을 비슷하게 맞춘다.
- 오답은 노트북에서 다룬 인접 개념, 흔한 오개념, 실행 순서 혼동 또는 설정 효과의 반대를 이용해 그럴듯하게 만든다.
- 말장난, 명백히 무관한 표현, "위 내용 모두", "정답 없음"을 선택지로 사용하지 않는다.
- 개념의 목적, 원리, 차이, 실행 결과, 호출 순서, shape 또는 설정 효과를 판단하게 한다.
- 함수명이나 메서드 이름만 단순 암기하는 문제는 만들지 않는다.
- 전체 문제에서 정답 위치가 1~4번에 고르게 분포하도록 하고 같은 위치가 세 문제 이상 연속되지 않게 한다.
- 주관식 전용 필드인 `acceptedAnswers`와 `keywords`는 생성하지 않는다.
- `solution`에는 정답 선택지 문자열을, `explanation`에는 정답 근거와 각 오답이 틀린 이유를 작성한다.

## API 빈칸 (`api`)

- 실행 가능한 완성 코드에서 핵심 API, 메서드, 인자, 옵션 또는 연산식만 빈칸으로 만든다.
- 빈칸은 `____[1]`, `____[2]` 형식만 사용한다.
- 빈칸 번호와 `blanks` 배열 순서를 일치시킨다.
- 각 blank의 `answer`를 반드시 같은 blank의 `choices`에 포함한다.
- `solution`은 모든 빈칸을 복원한 완전한 코드여야 한다.
- 같은 완성 코드에서 빈칸 위치만 바꾼 중복 문제를 만들지 않는다.
- 짧은 대입문만 떼어내지 말고 객체·입력 준비, 핵심 호출, 반환값 사용을 파악할 수 있는 앞뒤 코드를 남긴다.
- `content`에는 코드 목적, 준비된 객체와 데이터, 호출 뒤 이어질 동작을 설명한다.
- 오답 선택지는 인자 타입, 반환값, 호출 위치 또는 실행 흐름을 이해하면 구분할 수 있게 구성한다.
- 코드가 길면 한 단계의 파이프라인으로 줄이되 빈칸 앞뒤에 의미 있는 코드 문장을 남긴다.
- `explanation`은 각 정답의 역할과 입력→호출→결과 흐름을 연결해 설명한다.

## 생성 수량

- flow 객관식: {객관식_문제_수}
- api: {API_문제_수}

## 출력 형식

최종 출력은 다음 형태의 유효한 JSON 하나만 반환한다. 설명이나 Markdown 코드 펜스를 JSON 앞뒤에 출력하지 않는다.

```json
{
  "problems": []
}
```

각 문제는 공통으로 `id`, `unit`, `type`, `title`, `content`, `requirements`, `solution`, `explanation`, `example`을 사용한다. flow 객관식은 `choices`, `answer`를 추가하고 api는 `skeleton`, `blanks`를 추가한다.

`requirements`에는 문제별로 별도로 확인해야 하는 실질적인 조건만 작성한다. "정답 하나를 선택한다", "선택지 중 고른다"처럼 문제 형식만 반복하는 안내는 넣지 말고, 별도 조건이 없으면 빈 배열(`[]`)로 둔다.

flow 객관식은 다음 필드 형태를 따른다.

```json
{
  "id": "flow-unit-concept-001",
  "unit": "단원 번호",
  "type": "flow",
  "title": "평가할 개념",
  "content": "하나의 정답을 고를 수 있는 명확한 질문",
  "requirements": [],
  "choices": [
    "선택지 1",
    "선택지 2",
    "선택지 3",
    "선택지 4"
  ],
  "answer": "choices에 포함된 정답 선택지 문자열",
  "solution": "answer와 동일한 정답 선택지 문자열",
  "explanation": "정답의 근거와 각 오답이 틀린 이유",
  "example": ""
}
```

## 출력 전 검수

- 모든 필수 공통 필드가 있는가?
- 모든 ID가 고유한가?
- `type`이 `flow` 또는 `api`인가?
- 제목이 짧은 학습 개념을 나타내는가?
- 모든 flow 문제가 단일 정답 4지선다형인가?
- flow의 `choices`가 중복 없는 문자열 4개인가?
- flow의 `answer`가 `choices`에 정확히 포함되고 `solution`과 일치하는가?
- flow에 주관식 전용 `acceptedAnswers`와 `keywords`가 남아 있지 않은가?
- flow의 정답 위치가 전체 문제에서 고르게 분포하는가?
- flow의 해설이 정답 근거와 각 오답이 틀린 이유를 설명하는가?
- API 스켈레톤에서 객체 준비→핵심 호출→결과 사용을 확인할 수 있는가?
- API 빈칸 번호와 blanks 순서가 일치하는가?
- 모든 API 정답이 해당 choices에 포함되는가?
- solution에 빈칸 표식이 남아 있지 않은가?
- JSON 문자열의 줄바꿈이 `\n`으로 이스케이프되었는가?

최종 출력은 유효한 JSON만 반환하라.
